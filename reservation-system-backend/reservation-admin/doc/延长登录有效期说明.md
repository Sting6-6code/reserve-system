# 延长登录有效期说明

## 已完成的修改

### 配置文件修改

**文件位置**：`reservation-admin/src/main/resources/application.yml`

**修改内容**：
- **修改前**：`expireTime: 80` (80分钟，约1.3小时)
- **修改后**：`expireTime: 600` (600分钟，10小时)

## Token 过期时间说明

### 当前配置

- **Token 有效期**：10小时（600分钟）
- **自动刷新机制**：当剩余时间不足20分钟时，系统会自动刷新token

### Token 工作原理

1. **登录时**：系统生成token，有效期10小时
2. **使用过程中**：每次请求都会验证token
3. **自动刷新**：当token剩余时间不足20分钟时，系统会自动刷新，延长有效期
4. **过期后**：token过期后需要重新登录

### 代码实现位置

- **TokenService.java**：`reservation-framework/src/main/java/com/website/framework/web/service/TokenService.java`
  - `expireTime` 从配置文件读取（第45行）
  - `refreshToken()` 方法设置过期时间（第150行）
  - `verifyToken()` 方法自动刷新token（第132-140行）

### 2. 验证修改

**验证方法**：
1. 登录系统
2. 查看浏览器开发者工具中的token
3. 等待一段时间后，检查是否仍然可以正常使用系统

## 时间换算

- **10小时** = 600分钟
- **当前配置**：`expireTime: 600`

如果需要调整时间，可以使用以下换算：
- 1小时 = 60分钟
- 2小时 = 120分钟
- 5小时 = 300分钟
- 10小时 = 600分钟
- 12小时 = 720分钟
- 24小时 = 1440分钟

## 自动刷新机制

系统有一个自动刷新机制：
- 当token剩余时间不足**20分钟**时，系统会自动刷新token
- 刷新后，token的有效期会重新设置为10小时
- 这意味着如果用户持续使用系统，token会不断刷新，不会过期

**注意**：如果用户10小时内没有任何操作，token会过期，需要重新登录。

## 相关配置说明

### Token 配置项

```yaml
token:
  header: Authorization        # Token在HTTP头中的字段名
  secret: abcdefghijklmnopqrstuvwxyz  # Token签名密钥
  expireTime: 600             # Token有效期（分钟）
```

### Redis 缓存

Token信息存储在Redis中：
- **Key格式**：`login_tokens:{token_uuid}`
- **过期时间**：与token有效期相同（600分钟）
- **自动清理**：过期后Redis会自动删除

## 注意事项

1. **安全性**：较长的token有效期会降低安全性，建议：
   - 确保使用HTTPS
   - 定期更换token密钥
   - 监控异常登录行为

2. **内存占用**：较长的有效期会增加Redis中的token缓存数量

3. **用户体验**：10小时的有效期意味着用户一天内通常只需要登录一次

4. **时区问题**：确保服务器时区设置正确

## 常见问题

### Q: 修改后仍然很快过期？
A: 请确保：
1. 应用已重启
2. 配置已保存
3. 清除浏览器缓存和cookie，重新登录

### Q: 如何查看当前token的过期时间？
A: 可以通过以下方式：
1. 查看浏览器开发者工具的Network标签
2. 查看Redis中的token缓存（使用TTL命令）
3. 查看应用日志中的token相关信息

### Q: 可以设置更长的有效期吗？
A: 可以，但建议：
- 不超过24小时（1440分钟）
- 考虑安全性和用户体验的平衡
- 生产环境建议使用较短的过期时间

### Q: 如何强制用户重新登录？
A: 可以：
1. 修改token密钥（所有现有token会失效）
2. 清除Redis中的所有token缓存
3. 在用户管理界面强制用户下线

## 恢复默认值

如果需要恢复为默认值（30分钟），修改配置为：
```yaml
expireTime: 30
```

然后重启应用。
