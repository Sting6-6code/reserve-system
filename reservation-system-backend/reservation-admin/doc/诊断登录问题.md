# 登录问题诊断指南

## 问题现象
显示"用户名不存在/密码错误"，但用户名和密码没有修改过。

## 可能的原因

### 1. 数据库连接问题
- 检查数据库服务是否正常运行
- 检查数据库连接配置是否正确

### 2. 用户名查询问题
- 用户名大小写敏感（MySQL 在某些配置下区分大小写）
- 用户名前后可能有空格
- 用户名在数据库中不存在

### 3. 用户状态问题
- 用户被删除（`del_flag != '0'`）
- 用户被禁用（`status != '0'`）

### 4. 密码验证问题
- 密码加密方式不匹配
- 密码在数据库中存储格式错误

## 诊断步骤

### 步骤1：检查数据库连接

连接到数据库并执行以下 SQL：

```sql
-- 连接到数据库
mysql -h 127.0.0.1 -P 3306 -u root -p
-- 输入密码：NiubiSPA

-- 使用数据库
USE reservation-system;

-- 检查数据库连接
SELECT 1;
```

### 步骤2：检查用户是否存在

```sql
-- 查看所有用户（替换 'admin' 为你的实际用户名）
SELECT user_id, user_name, nick_name, status, del_flag, password 
FROM sys_user 
WHERE user_name = 'admin';

-- 如果查询结果为空，尝试不区分大小写查询
SELECT user_id, user_name, nick_name, status, del_flag, password 
FROM sys_user 
WHERE LOWER(user_name) = LOWER('admin');

-- 查看所有用户列表
SELECT user_id, user_name, nick_name, status, del_flag 
FROM sys_user 
ORDER BY user_id;
```

### 步骤3：检查用户状态

```sql
-- 检查用户是否被删除或禁用
SELECT 
    user_id,
    user_name,
    nick_name,
    status,           -- '0'=正常, '1'=停用
    del_flag,        -- '0'=正常, '2'=删除
    password
FROM sys_user 
WHERE user_name = 'admin';
```

**重要检查项：**
- `del_flag` 必须为 `'0'`（如果为 `'2'` 表示用户已被删除）
- `status` 必须为 `'0'`（如果为 `'1'` 表示用户已被停用）

### 步骤4：修复用户状态（如果需要）

如果用户被删除或停用，执行以下 SQL 修复：

```sql
-- 如果用户被删除，恢复用户
UPDATE sys_user 
SET del_flag = '0' 
WHERE user_name = 'admin';

-- 如果用户被停用，启用用户
UPDATE sys_user 
SET status = '0' 
WHERE user_name = 'admin';
```

### 步骤5：检查密码格式

```sql
-- 查看密码字段（BCrypt 加密的密码应该以 $2a$ 或 $2b$ 开头）
SELECT user_name, 
       LEFT(password, 10) as password_prefix,
       LENGTH(password) as password_length
FROM sys_user 
WHERE user_name = 'admin';
```

BCrypt 加密的密码格式：
- 应该以 `$2a$` 或 `$2b$` 开头
- 长度通常为 60 个字符

## 常见问题解决

### 问题1：用户名大小写不匹配

MySQL 在 Linux 系统上默认是大小写敏感的，在 Windows 上默认不敏感。

**解决方案：**
```sql
-- 检查实际存储的用户名
SELECT user_name FROM sys_user WHERE LOWER(user_name) = LOWER('admin');

-- 如果用户名大小写不匹配，更新为正确的大小写
UPDATE sys_user SET user_name = 'admin' WHERE LOWER(user_name) = LOWER('admin');
```

### 问题2：用户名前后有空格

**解决方案：**
```sql
-- 检查用户名是否有空格
SELECT user_name, LENGTH(user_name) as len, 
       CONCAT('|', user_name, '|') as with_pipes
FROM sys_user 
WHERE user_name LIKE '%admin%';

-- 清理用户名前后的空格
UPDATE sys_user 
SET user_name = TRIM(user_name) 
WHERE user_name LIKE '%admin%';
```

### 问题3：数据库连接配置错误

检查 `application-druid.yml` 文件中的数据库配置：
- 数据库地址：`127.0.0.1:3306`
- 数据库名：`reservation-system`
- 用户名：`root`
- 密码：`NiubiSPA`

### 问题4：应用日志检查

查看应用日志文件，查找具体的错误信息：
- 查看是否有数据库连接错误
- 查看是否有 SQL 执行错误
- 查看用户查询的详细日志

## 快速诊断脚本

创建一个 SQL 诊断脚本：

```sql
-- 完整诊断脚本
SET @username = 'admin';  -- 替换为实际用户名

SELECT 
    '=== 用户基本信息 ===' as info;
    
SELECT 
    user_id,
    user_name,
    nick_name,
    status,
    del_flag,
    CASE 
        WHEN del_flag = '0' THEN '✓ 未删除'
        WHEN del_flag = '2' THEN '✗ 已删除'
        ELSE '? 未知状态'
    END as del_status,
    CASE 
        WHEN status = '0' THEN '✓ 正常'
        WHEN status = '1' THEN '✗ 停用'
        ELSE '? 未知状态'
    END as user_status,
    LEFT(password, 20) as password_preview
FROM sys_user 
WHERE user_name = @username;

SELECT 
    '=== 诊断结果 ===' as info;

SELECT 
    CASE 
        WHEN COUNT(*) = 0 THEN '✗ 用户不存在'
        WHEN MAX(del_flag) != '0' THEN '✗ 用户已被删除'
        WHEN MAX(status) != '0' THEN '✗ 用户已被停用'
        WHEN MAX(password) IS NULL OR MAX(password) = '' THEN '✗ 密码为空'
        WHEN MAX(password) NOT LIKE '$2%' THEN '✗ 密码格式异常（不是 BCrypt 格式）'
        ELSE '✓ 用户状态正常，请检查密码是否正确'
    END as diagnosis
FROM sys_user 
WHERE user_name = @username;
```
